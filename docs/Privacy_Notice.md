## 1. The short version

UNI Made EZ is a study application that runs **entirely inside the student's web browser**. Course
files a student adds — PDFs, slide decks, documents — are opened and read by JavaScript already
running on their device. **No file, and no text taken out of a file, is ever transmitted.** Cards,
answers, ratings, progress, notes and exam dates are held in that browser's own storage on that
device, and nowhere else.

The application transmits exactly two things, both described in full below:

1. an **anonymous open-counter** message, at most once an hour, so the publisher knows roughly how
   many people use the app; and
2. a **name and email address**, *only* if a student chooses to type them into an optional sign-up
   form and press the button.

There are no cookies, no advertising identifiers, no analytics services, no third-party scripts of
any kind, no location, no fingerprinting, and no sale or sharing of anything with anyone.

## 2. Personal information collected

### 2.1 The open counter — not personal information about an identifiable individual

Sent at most once per hour, only when the app is opened, to a Postgres database operated by the
publisher. It contains seven items and nothing else:

| Item | What it is |
|---|---|
| Device id | A random string generated by the browser on first use. Not derived from the device, the network, the user, or anything about them. Meaningless outside this counter. |
| Times opened | An integer. |
| Subjects started | An integer. Never the names of subjects, never their contents. |
| Signed up | Boolean. |
| Device family | One of `iOS`, `Android`, `Mac`, `Windows`, `Linux`, `Other`, plus whether the app was installed to the home screen. |
| Time zone | The IANA name the browser reports, e.g. `America/Vancouver`. |
| Time | Set by the database on arrival, not sent by the client, so a misconfigured device clock cannot distort counts. |

No IP address is stored. Clearing browser site data discards the device id and the next visit counts
as a new device — a deliberate accuracy cost accepted in exchange for not following anyone.

### 2.2 Name and email — personal information, collected with consent

- **Collected only** when the individual types them into the sign-up form and submits it.
- **Entirely optional.** Since v2.27 **no feature of the application is withheld** from someone who
  declines. Every course, card, summary, quiz, essay tool and export works identically. Earlier
  versions gated two features behind sign-up; that was removed because consent obtained as the price
  of access to study material is not meaningful consent.
- **Purposes**, stated before collection at both points where it can be given: (a) to know who is
  using the application; (b) to contact the individual about the application.
- **Not used for** advertising, profiling, scoring, resale, disclosure to any third party, or any
  purpose beyond (a) and (b).

### 2.3 What is never collected, by design

Course files; text extracted from them; flash cards; quiz answers; scores; study progress; notes;
exam dates; search terms; institution; student number; course enrolment; IP address; precise or
approximate location; browsing history; contacts; any biometric or device-identifying signal.

## 3. Where it is stored, and who can reach it

- **Storage:** PostgreSQL hosted by Supabase, **Canadian region `ca-central-1`**. Personal
  information does not leave Canada.
- **In transit:** HTTPS/TLS only. **At rest:** encrypted by the platform.
- **Access control:** the API key embedded in the published page is a *publishable* key. The
  database uses row-level security configured so that key may **write** a row and may **not read one
  back**. The table holding names and emails has no read policy for it at all. The publisher's own
  statistics panel reads a database view returning **counts only** — it cannot return a name.
- **Verified, not assumed.** This was tested against the live database by attempting to read the
  rows using the key that ships in the page and being refused. A configuration screen saying the
  right thing is not evidence; a refused read is.
- **Who can read personal information:** JohnsonXCorp, authenticated to that database. Nobody else.
- **Sub-processor:** Supabase Inc. (database hosting). GitHub, Inc. serves the static page and
  receives ordinary web-server request logs as any web host does; it receives no application data.

## 4. Retention

| Data | Retained |
|---|---|
| Name and email | Until deletion is requested, and in any event when the application is retired. Deleted **within 30 days** of a request. |
| Open-counter rows | While the application is published. They contain no personal information. |
| On-device data (files, cards, progress) | Under the individual's sole control. Deleted instantly and permanently by clearing browser site data. |

## 5. Rights, and how to use them

Under BC PIPA an individual may **ask what is held about them and receive a copy**, **have it
corrected**, **have it deleted**, and **withdraw consent** at any time, for any reason or none.

- **How:** email the privacy contact above. No form, no fee, no reason required. "Delete me" is a
  valid request.
- **Timeline:** answered within **30 business days**, the limit PIPA sets.
- **Escalation:** a complaint may be made to the Office of the Information and Privacy Commissioner
  for British Columbia, <https://www.oipc.bc.ca>, which can investigate independently.
- **On-device data** needs no request at all: clearing site data deletes it, immediately and
  without anyone's permission.

## 6. Breach

If the sign-up table were compromised, every affected individual would be notified directly and the
Commissioner would be notified. British Columbia does not presently make that report mandatory for
private organisations; it would be made regardless.

## 7. Children

The application is built for post-secondary students and is not directed at children. No age is
collected, because collecting one would mean collecting more personal information than the
application needs.

## 8. Verifiability

Every claim in section 2 is checkable without trusting this document:

- The entire application is delivered to the browser as one readable page. Open the browser's
  network panel, add a course file, and observe that no request is made.
- The app works with the network switched off, which is only possible because it does not need one.
- The source is public at <https://github.com/ThePastor/uni-made-ez>.
- **`test/legal.js`** in that repository loads real documents into a real subject with every
  outbound request and request body recorded, then asserts that no request left the origin, that no
  request body existed at all, and that no word of the material appeared in any request. It also
  compares the seven-row table in the app against the fields the code actually sends, so adding an
  eighth field without disclosing it fails the build.

## 9. Changes

The counter was added in v2.19. Until v2.27 this application's privacy text still said that nothing
at all left the browser, which the counter had made untrue. The sentence was corrected rather than
kept, the history of the correction is stated in the app itself, and an automated test now fails the
build if the absolute claim ever returns. Material changes to this notice will be recorded in the
application's version history, which is visible in the app footer.
